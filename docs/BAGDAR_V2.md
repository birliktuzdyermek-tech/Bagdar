# БАҒДАР — доработка V2

> Дополнение к `BAGDAR.md`, `BAGDAR_PLAN.md` и стартовому промту.
> Этот файл получают все три сессии. Он задаёт общие правила, чтобы три независимые части выглядели и работали как один продукт.
> Версия 0.3 от 01.10.2026.

---

## 1. Три сессии, три деплоя

| Сессия | Что строит | Что деплоит | За что отвечает на защите |
|---|---|---|---|
| **1. Ядро** | Симулятор, планировщик, экран диспетчера, лёгкий режим | Приложение с сервером | Критерии «планирование», «backend», живое перепланирование |
| **2. Витрина** | Анимированный сайт-презентация, галерея ситуаций, режим показа слайдов | Статический сайт | Первое впечатление, рассказ, запасной вариант без интернета |
| **3. Сеть** | Реальные схемы линий, пакеты сценариев, иерархия диспетчеров, средний и ультра-режим, замеры | Отдельное приложение «Сеть» | Масштаб, реальные данные, цифры для слайдов |

### Правила, чтобы сессии не мешали друг другу

1. **У каждой области один хозяин.** Сессия не правит чужой код. Если всё лежит в одном репозитории, сессия 2 работает только в `showcase/`, сессия 3 только в `network/` и `data/`.
2. **Связь через три формата данных**, которые задаёт Ядро:
   - `world` — сеть: станции, пути, перегоны, сигналы;
   - `scenario` — расписание, список сбоев по времени, seed;
   - `replay` — журнал событий одного прогона, по которому прогон можно показать заново.
3. **Никаких выдуманных прогонов.** Витрина показывает только записи настоящих расчётов из Ядра или Сети и подписывает их «запись прогона». Живое помечается «в реальном времени».
4. **Одна шапка на трёх сайтах:** «Симулятор», «Сеть», «Презентация». Адреса задаются в конфиге.
5. **Один стиль.** Цвета, шрифты и скорости анимации берутся из одного файла токенов. Если в Ядре стиль уже есть, главным считается он.

### Порядок запуска

1. Сессия 1 выгружает пакет `contracts/`: схемы трёх форматов, описание событий, один пример записи прогона, файл токенов стиля.
2. Сессии 2 и 3 стартуют с этим пакетом.
3. По мере готовности Ядро и Сеть отдают записи прогонов, они кладутся в Витрину.
4. В конце в каждый конфиг вписываются три адреса.

## 2. Стиль, анимация, доступ

### Экран в зале

На фото с презентации кейса видно: огромная светодиодная стена, мелкий серый текст на ней не читается совсем. Отсюда правила.

- Основной текст не меньше 16 px на ноутбуке, в режиме показа не меньше 24 px.
- Никакого тонкого серого текста. Контраст текста к фону не ниже 4,5 к 1.
- Линии схем не тоньше 2 px.
- Есть переключатель «режим проектора»: крупнее шрифт, толще линии, меньше деталей.

### Токены по умолчанию

```css
:root {
  --bg: #0B1220;          /* фон */
  --surface: #131C2E;     /* панели */
  --line: #2A3650;        /* границы, пути */
  --text: #EEF3FB;
  --text-2: #B4C0D6;      /* вторичный текст, не светлее */
  --accent: #2DD4BF;      /* действия Бағдара */
  --ok: #22C55E;          /* норма */
  --warn: #F59E0B;        /* внимание */
  --crit: #EF4444;        /* критично */
  --info: #60A5FA;

  --t-fast: 150ms;        /* отклик на нажатие */
  --t-base: 300ms;        /* появление, смена состояния */
  --t-slow: 700ms;        /* перестройка плана, смена масштаба */
  --ease: cubic-bezier(0.2, 0.8, 0.2, 1);
}
```

Классы поездов различаются не только цветом, но и формой метки: пассажирский круг, грузовой прямоугольник, внеочередной ромб. Статус дублируется словом и значком. Так интерфейс читается при любом зрении и на любом экране.

### Анимация: всё движется, и всё со смыслом

Каждая анимация показывает изменение состояния. Украшений ради украшений нет.

| Что | Как движется |
|---|---|
| Поезда | Плавно, с интерполяцией между обновлениями, без рывков |
| Перестройка плана | Старые линии графика перетекают в новые за 700 мс, изменённые подсвечены |
| Индекс | Число перелистывается, шкала плавно меняет цвет |
| Сбой | Волна от точки сбоя расходится по схеме и показывает, кого заденет |
| Решение | Карточка выезжает, на схеме вспыхивает место, к которому она относится |
| Буран, туман, отключение питания | Фронт ползёт по карте, поезд расплывается в полосу, участок гаснет |
| Смена масштаба | Плавный переход от сети к участку и к поезду |
| Счётчики | Числа докручиваются, а не прыгают |

Технические условия: 60 кадров в секунду в лёгком режиме, не ниже 30 в ультра. Всё массовое рисуется на холсте. Учитывается системная настройка «меньше движения»: при ней остаются только смены состояний.

### Лёгкий доступ

- Открывается по ссылке, без установки и регистрации.
- Первый экран загружается за 3 секунды.
- Работает на телефоне, планшете и ноутбуке. На телефоне упрощённый вид: индекс, схема, лента решений.
- **Режим витрины:** если 30 секунд никто ничего не трогает, сайт сам запускает тур по сценариям.
- **Работа без интернета:** Витрина несёт записи прогонов внутри себя. Если в зале пропала сеть, показ продолжается.
- Управление с клавиатуры, видимый фокус, подписи у всех кнопок.

## 3. Реальные схемы

Правило из условий кейса: реальные коммерческие данные не используются. Поэтому граница такая.

- **Настоящее:** география линии, названия и порядок станций, число путей, длины перегонов. Источник — открытые карты (OpenStreetMap, OpenRailwayMap) и открытые публикации.
- **Смоделированное:** поезда, расписание, загрузка, сбои.
- **Подпись на экране:** «Схема по открытым данным. Движение смоделировано».

Если точной цифры нет, ставится приближённая с пометкой. Выдавать приближение за точные данные нельзя.

### Три цифровых двойника

**А. Достык – Мойынты.** Главная линия для демонстрации.
836 км, транзитный коридор Китай – Европа. Однопутной линия пропускала 12 пар грузовых поездов в сутки. Проектная пропускная способность после второго пути — 60 пар грузовых в сутки (это проект, не замер). По публикации на январь 2026 года реально шло около 18 поездов в сутки по новому пути и 19 по старому.
Делаются две версии одной линии: однопутная и двухпутная. 60 пар — это 120 поездов в сутки, то есть ровно средний режим.
Зачем: комиссия знает эту линию. И на ней задаётся самый сильный экономический вопрос (раздел 4).

**Б. ЛРТ Астаны.** Профиль `mode: lrt`.
18 станций, 22,4 км, поезда без машинистов, интервал 5–6 минут. Здесь нет классов поездов, задача другая: ровный интервал. Показывает, что Бағдар умеет переключать саму цель оптимизации.

**В. Сеть.** Ультра-режим.
Упрощённая схема магистральной сети по открытой карте: узлы, коридоры, объезды. 200 станций, 10 зон. Подпись: «стресс-тест, нагрузка выше реальной».

## 4. Экономика

### Панель «Цена»

- У каждого решения есть цена и цена альтернативы.
- Три живых счётчика: минуты задержки, энергия, условные деньги. Каждый показывает «с Бағдаром» и «без».
- Пересчёт на сутки и на год по текущему прогону.

### «Подставьте свой тариф»

Поля ввода: цена кВт·ч, цена часа локомотива, цена часа бригады, цена минуты задержки пассажирского и грузового поезда. Комиссия вводит свои числа, все счётчики пересчитываются на месте.

Это превращает слабое место («цифры условные») в сильное: «мы не знаем ваших тарифов, введите их сами».

### Главный экономический опыт

На однопутной версии Достык – Мойынты один и тот же поток поездов пропускается дважды:
- правило «кто первый пришёл, тот первый едет»;
- Бағдар.

Измеряется, сколько поездов в сутки проходит без роста задержек в каждом случае. Разница — это пропускная способность, полученная без укладки рельсов. Число выводится на отдельный слайд рядом с двумя реальными фактами: второй путь по проекту поднимает способность с 12 до 60 пар; цифровая автоблокировка на участке Кызылжар – Саксаульская (712 км) уже подняла её с 8 до 20 пар грузовых в сутки без новых рельсов.

Формулировка на защите честная: «в нашей модели», без обещаний реальной экономии.

## 5. Решения, которые выглядят неправильно

Раздел про то, что человек сам бы не сделал. Система принимает решение, которое на первый взгляд ошибочно, и тут же доказывает, что оно верное.

| Решение | Почему кажется ошибкой | Почему оно верное |
|---|---|---|
| **Медленнее значит быстрее.** Всем поездам пачки снижена скорость | Тормозим движение при перегрузке | Исчезают остановки и разгоны, участок пропускает больше |
| **Жертва.** Скорый задержан на 2 минуты прямо сейчас | Трогаем самый важный поезд | Через час он избегает задержки на 25 минут |
| **Пустой перегон.** Свободный перегон не занимается намеренно | Простаивает ресурс | Это запас, который не даёт участку запереться |
| **Длинный путь короче.** Поезд уходит в объезд на 40 км | Лишний пробег | Приходит раньше, чем дождался бы очереди |
| **Стоять на зелёный.** Поезд придержан на станции при свободном пути | Путь свободен, почему стоим | Впереди через 20 минут затор, на перегоне стоять дороже |
| **Младший вперёд.** Тяжёлый грузовой пропущен раньше пассажирского | Нарушен порядок классов | У пассажирского есть запас, он приходит вовремя, грузовой не остановлен на подъёме |

### Как это показывается

Карточка с пометкой «неочевидное решение». Кнопка **«Докажи»** запускает два будущих рядом на ускорении: с этим решением и без него. Через 10 секунд разница видна в цифрах.

Человеку не нужно понимать расчёт. Ему достаточно увидеть оба исхода.

## 6. Функции для комиссии

Упорядочено по силе эффекта. Первые шесть обязательны, остальные по времени.

1. **«Сломайте сами».** На экране QR-код. Член комиссии открывает страницу на своём телефоне и нажимает «закрыть перегон», «отключить подстанцию», «буран». Событие приходит в живую симуляцию, система отвечает за секунды. Доказывает, что ничего не отрепетировано.
2. **«Назовите число».** Любое число из зала становится зерном генератора. Собирается уникальная авария, которой нет в библиотеке, и решается на месте.
3. **«Сядьте за пульт».** Член комиссии 60 секунд сам управляет участком на 20 поездов. Рядом тот же сценарий ведёт Бағдар. В конце два счёта.
4. **«Докажи».** Два будущих рядом (раздел 5).
5. **«Подставьте свой тариф»** (раздел 4).
6. **«Попробуйте нарушить безопасность».** Человек вручную отдаёт опасную команду. Система отказывает и объясняет, какое ограничение нарушено. На экране счётчик: «проверено планов: N, конфликтов: 0».
7. **Сутки за 60 секунд.** Полный день работы линии на ускорении со счётчиками.
8. **Три будущих.** При тяжёлом сбое три варианта прокручиваются параллельно, выбирается лучший.
9. **Голосовой доклад.** Бағдар коротко произносит, что случилось и что сделано. Используется встроенный синтез речи браузера, без платных сервисов.
10. **До и после второго пути.** Одна линия в двух версиях на разделённом экране.
11. **Отчёт на руки.** PDF по только что показанному прогону с QR-кодом на его запись.

## 7. Презентация внутри сайта

Требование хакатона — 10–12 слайдов с архитектурой и формулой индекса. Они делаются частью Витрины: режим показа, листание стрелками, каждый слайд живой.

1. **Проблема.** 190, 4 950, 499 500 пар. Число растёт на глазах вместе с поездами на фоне.
2. **Диспетчер сегодня.** Что он держит в голове.
3. **Бағдар.** Что это и чего он не делает.
4. **Живой участок.** Запись прогона лёгкого режима.
5. **Сбой.** План перестраивается, время пересчёта на экране.
6. **Приоритеты.** Четыре слоя.
7. **Неочевидное решение** и кнопка «Докажи».
8. **Индекс.** Формула, веса, пороги, смена весов на лету.
9. **Архитектура.** Схема модулей и потока данных.
10. **Масштаб.** Иерархия, 1 000 поездов, замеры времени.
11. **Экономика.** Достык – Мойынты, свой тариф.
12. **Ограничения и развитие.** Консультативная система, условные данные.

Последний слайд содержит QR на «Сломайте сами».

## 8. Риски

- **Три сессии расходятся.** Лечится пакетом `contracts/` и правилом «один хозяин». Без пакета сессии 2 и 3 не запускать.
- **Ядро отстаёт от украшений.** Баллы дают планирование и backend. Если времени мало, урезаются сессии 2 и 3, а не Ядро.
- **Интернет в зале.** Витрина обязана работать без сети. Живой симулятор запускается и с ноутбука.
- **«Сломайте сами» требует адреса, доступного с телефонов.** Проверить в зале заранее. Запасной вариант: те же кнопки нажимает выступающий.
- **Слишком много функций.** Шесть отточенных сильнее одиннадцати сырых.
- **Честность цифр.** Условное подписано как условное, запись как запись, приближение как приближение.
