# Контракты Бағдар, версия 1

Этот пакет связывает «Ядро», «Сеть» и «Витрину». Три файла схемы используют JSON Schema Draft 2020-12. Время во всех файлах — секунды модели от 00:00 01.10.2026, UTC+5; координаты станций `x/y` — координаты схемы, не географические. `world.version` — версия загруженного мира в рамках процесса, а не версия схемы.

| Формат | Схема | Пример | Источник |
| --- | --- | --- | --- |
| `world` | `world.schema.json` | `examples/world.light.json` | `WorldOut` и `SimulationRuntime.world_payload()` |
| `scenario` | `scenario.schema.json` | `examples/scenario.light.json` | `Scenario`, исходный YAML сценария |
| `replay` | `replay.schema.json` | `examples/replay.light.json` | реальные шаги `Engine`, через `SimulationRuntime` |

`replay` самодостаточен: содержит `world`, `scenario`, полный исходный план, снимки состояния и все события на интервале записи. Пример охватывает 06:00–06:02 с кадром каждые 10 секунд модели. Это запись штатного движения с seed 42; названия станций и движение сгенерированы симулятором. Сбои в этом примере отсутствуют. Пока ядро не выдаёт вычисленный индекс, `frames[].index` равен `null`; витрина должна показать «индекс пока не рассчитан», а не число. Когда индекс появится, в этом поле будут его значение, факторы и статус.

## Воспроизведение на любой момент `t`

1. Прочитать `world` для схемы, поездов и исходного расписания. Проверить `schema_version` у `replay`.
2. Найти последний элемент `plans` с `plan.t <= t`. Его `plan` — действующий план. Если такого элемента нет, план ещё не известен.
3. Найти два соседних `frames` вокруг `t`. Первый — полный авторитетный снимок. Для поезда на том же перегоне в обоих кадрах можно линейно интерполировать `progress`; при смене `status` или `section_id` использовать первый кадр до времени следующего. При отсутствии следующего кадра держать последний снимок. Нельзя экстраполировать маршрут за пределы записи.
4. Счётчики и занятость ресурсов брать из первого снимка; они меняются дискретно. `index` брать из последнего кадра с временем не позже `t`. `null` означает, что расчёта нет. Число между кадрами допускается интерполировать только для визуального перехода, не как новое измерение.
5. Показать события с `event.t <= t` в порядке `seq`. `events.md` описывает типы и поля.

Запись можно воспроизвести офлайн, без API. `state.trains[].progress` всегда от станции `a` к `b` из `world.sections`, независимо от направления поезда. Для плавности визуальный интерполятор не должен менять принадлежность поезда перегону до следующего снимка.

## Совместимость и обновление

Для версии 1 сохраняются значения и смысл существующих полей. Новые поля только необязательные; старые файлы должны оставаться читаемыми. Новые типы событий допускаются, неизвестные `kind` показываются по `message`. Несовместимое изменение требует нового `schema_version`, отдельного описания миграции и сообщения другим сессиям.

Экспорт заново: `python contracts/export.py` из корня репозитория с установленными зависимостями `backend/requirements.txt`. Скрипт валидирует реальные данные Pydantic-моделями и записывает схемы и примеры. `run_id` и измерения производительности меняются между запусками; геометрия и движение при том же seed повторяемы.
